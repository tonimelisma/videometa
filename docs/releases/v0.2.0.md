## Summary

`v0.2.0` is the first release after the pre-1.0 reset of `videometa` into a video-native-only package. It combines the API and scope cleanups that landed after `v0.1.0` with a release-on-merge pipeline: every merged increment now has to carry a version bump, release notes, and hosted CI that restores the full validated fixture corpus before it can publish a Go module tag and GitHub Release.

## API / behavior changes

- Replaced the old lossy collected API with `DecodeAll(Options) (Metadata, error)` and a lossless `Tags` -> `SourceTags` -> `NamespaceTags` hierarchy.
- Removed MakerNotes and all embedded image-metadata routes from the public product model; `videometa` now exposes only `QUICKTIME`, `VENDOR`, `CONFIG`, and `COMPOSITE`.
- Tightened namespace and source semantics so vendor families live under stable `VENDOR` route identities instead of overloading `QUICKTIME`.
- Split the old catch-all runtime helper layer into focused video-metadata modules for errors, timestamps, GPS, text sanitization, and numeric coercion.

## New validated fixture coverage

- Added and validated committed real-fixture goldens for `IMG_5179.MOV`, `google.mp4`, and `sony_a6700.mp4`, plus bootstrap-downloadable GoPro and DJI real-fixture goldens.
- Added duplicate-preserving ordered exiftool goldens across the real-fixture corpus, not just grouped JSON goldens.
- Added bootstrap automation and acquisition docs for the scriptable GoPro and DJI fixture set, and retired `apple.mov` from the validated corpus in favor of the smaller committed `IMG_5179.MOV` fixture.

## exiftool parity fixes

- Fixed Sony NRTM repeated-item handling so GPS-related XML values no longer collapse to a single entry.
- Fixed Google/Android container metadata parity around `mdta`, `mett`, `colr/nclx`, and language-code behavior.
- Fixed GoPro repeated vendor tags and GPMF-derived values that the broader ordered-golden layer exposed.
- Fixed DJI-specific `stsd` child-atom handling, `fiel`/field-order extraction, and large-tag default handling so the Ronin and Inspire fixtures match exiftool.
- Replaced the older flat-only golden strategy with grouped plus ordered occurrence validation to catch duplicate-tag mismatches directly.

## Scope-policy changes

- Embedded image metadata payloads are now an explicit non-goal. `videometa` does not parse EXIF/TIFF, XMP/RDF, or IPTC-IIM payloads carried inside video containers.
- Validation claims are real-file-only. Synthetic fixtures remain useful for parser-hardening regressions, but they do not count as validated product support.
- The repo now treats every merge to `main` as release-producing: `VERSION` is the single source of truth, release notes are reviewed in PRs, and publish happens only after hosted CI restores the bootstrap-downloadable fixtures and passes on the exact `main` commit.

## Known remaining gaps

- Canon or Panasonic professional-camera fixture coverage is still pending.
- A 64-bit box-size real or crafted fixture is still pending.
- Additional vendor families should only be added if they are genuinely video/container metadata and can be validated against real video fixtures.
